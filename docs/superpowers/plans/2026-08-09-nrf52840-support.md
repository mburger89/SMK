# nRF52840 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `ports/nrf52840/` as a new SMK build target for Nordic's nRF52840 (Arm Cortex-M4F), covering USB HID and BLE HID, build-only (no hardware on hand).

**Architecture:** New port directory mirroring `ports/rp2040/`'s shape. GPIO and USB HID follow patterns already proven in the existing ESP32-C6/RP2040 ports closely. BLE is the novel piece: Nordic's SoftDevice Controller (SDC, a prebuilt static library exposing standard HCI) plugs into BTstack via a custom `hci_transport_t` implementation, but SDC itself has no generic "send raw HCI command bytes" entry point — every command needs its own typed function call. Rather than write that dispatch layer from scratch, this plan vendors and adapts Nordic's own `hci_internal.c`/`.h` (from `nrfconnect/sdk-nrf`, same license as SDC/MPSL, already raw-byte-buffer-based, not tied to Zephyr's `net_buf`) to do it.

**Tech Stack:** Embedded Swift (`armv7em-none-none-eabi`), `arm-gcc-bin@14`, CMake/Ninja, Nordic's nRF5 SDK (CMSIS device header + Cortex-M4 startup/linker script — verified as the actual current source, since modern `nrfx` no longer bundles these), `nrfconnect/sdk-nrfxlib` (prebuilt SDC + MPSL libraries), TinyUSB (`nrf5x` device driver), BTstack.

## Global Constraints

- Build-only: no nRF52840 hardware on hand. No flash/HID/BLE verification — every task's regression check is "does it build and link cleanly."
- Board: `nrf52840dk` (Nordic's official PCA10056 dev kit) only, this pass.
- Chip/ABI: Arm Cortex-M4F, **soft-float** throughout (`armv7em-none-none-eabi` on the Swift side, `-mfloat-abi=soft` on the C side) — verified as the only variant with a real Embedded Swift stdlib on any installed toolchain, and SDC/MPSL both ship a matching soft-float prebuilt variant, so there's no ABI mismatch to design around.
- `Sources/SMKCore/` is reused unmodified — this port only adds hardware-touching Swift/C files, never touches shared pure-logic code.
- Every C file added under Nordic's `LicenseRef-Nordic-5-Clause` (SDC, MPSL, the adapted `hci_internal.c`/`.h`, the CMSIS/startup files) must keep its copyright header — that license permits redistribution "as embedded into a Nordic Semiconductor ASA integrated circuit in a product," which this is.
- Four new vendor dependencies, each a plain git-clonable/downloadable directory referenced by an env var (same pattern as `PICO_SDK_PATH`): `NRF5_SDK_PATH` (CMSIS device header + startup + linker script), `NRFXLIB_PATH` (prebuilt SDC + MPSL libraries), `TINYUSB_PATH` (USB device stack), `BTSTACK_PATH` (BLE host stack — RP2040 gets this bundled via pico-sdk; nRF52840 has no such SDK, so it's vendored independently here).
- **New project code favors Swift over C wherever the C library's calling convention allows it** — matching the precedent already set this session for ESP32-C6 (`Sources/smk/GPIOInit.swift`/`SmkConfig.swift`, which replaced C files calling the same vendor driver functions). Concretely: any C API callable via `@_extern(c, ...)` (plain function calls into a vendor library — GPIO register pokes, `mpsl_init`, TinyUSB's `tud_*` functions) gets a thin Swift wrapper instead of a `.c` file; any C-linkage entry point a vendor library calls *into* by symbol name (TinyUSB's `tud_hid_get_report_cb`-style weak callbacks, this chip's interrupt vector table entries) is a Swift function exposed via `@_cdecl(...)`, exactly like `app_main_swift` already is. This does **not** extend to: the C `main()` stub (needs real C-runtime entry-point linkage, matches every existing port), vendored/adapted third-party source (Task 6's Nordic dispatcher — porting ~2000 lines of vendored C to Swift would defeat the point of reusing it), or constructing C-ABI **structs of function pointers** as literals (BTstack's `hci_transport_t` in Task 7 — Embedded Swift has no clean syntax for a `static const` struct-of-C-function-pointers the way C does; the individual callback *bodies* still move to Swift, only the struct literal gluing their symbol names together stays a few lines of C).

- [ ] **Step 1: Write `GPIORegisters.swift`**

The `nrf52840dk`'s matrix pin map (which physical GPIOs) isn't looked up in this plan (deferred, matching the design spec's own deferral) — this file only needs P0 (pins 0-31), since a 59-key matrix comfortably fits in one port's 31 usable GPIOs... actually a 5x12 matrix needs 17 pins (5 rows + 12 cols), well within P0 alone. Create `ports/nrf52840/GPIORegisters.swift`:

```swift
// nRF52840 GPIO (P0) raw register access — same outSet/outClear/input API
// as Sources/smk/GPIORegisters.swift (ESP32-C6) and
// ports/rp2040/GPIORegisters.swift (RP2040/RP2350). P0 only (GPIO 0-31) —
// this board's matrix fits comfortably within P0, so P1 (pins 32-47) is
// unused and not wired up here.
//
// Register offsets verified against Nordic's nRF52840 Product
// Specification during this port's feasibility spike:
// docs/superpowers/specs/2026-08-09-nrf52840-support-design.md.
struct GPIORegisters {
    static let base: UInt32 = 0x50000000

    var outSet: UInt32 {
        get { UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x508))!.pointee }
        nonmutating set { UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x508))!.pointee = newValue }
    }

    var outClear: UInt32 {
        get { UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x50C))!.pointee }
        nonmutating set { UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x50C))!.pointee = newValue }
    }

    var input: UInt32 {
        UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x510))!.pointee
    }
}

let gpio = GPIORegisters()
```

(This mirrors the exact shape of the existing two `GPIORegisters.swift` files — read one of them first to match the precise property-accessor style used there, since this plan's authors haven't re-read that file's exact syntax before writing this task.)

- [ ] **Step 2: Write `GPIOInit.swift`**

`PIN_CNF[n]` bit layout (Nordic Product Specification, standard across the nRF52 series): bit 0 = `DIR` (0=input, 1=output), bit 1 = `INPUT` (0=connect input buffer, 1=disconnect — inverted), bits 2-3 = `PULL` (00=disabled, 01=pulldown, 11=pullup), bits 8-10 = `DRIVE` (000=S0S1 standard drive, the default/safe choice), bit 16 = `SENSE` (00=disabled). Per this plan's Swift-first preference (Global Constraints), this is a plain Swift function using raw `UnsafeMutablePointer` writes — no C file at all, matching `GPIORegisters.swift`'s own style for the exact same register block, and mirroring how `Sources/smk/GPIOInit.swift` already made this same file-elimination move for ESP32-C6 (there, by calling ESP-IDF driver functions via `@_extern(c)`; here it's even more direct since there's no vendor driver call to wrap, just raw register pokes Swift can do natively).

Create `ports/nrf52840/GPIOInit.swift`:

```swift
// nRF52840 matrix pin configuration — same role as
// Sources/smk/GPIOInit.swift (ESP32-C6) and
// ports/rp2040/platform/gpio_init.c (RP2040, still C there). Plain Swift
// here: PIN_CNF is a raw register, so there's no vendor driver call to
// wrap via @_extern(c) the way ESP32-C6's version needs — just direct
// UnsafeMutablePointer writes, same style GPIORegisters.swift already
// uses for the scan loop itself.
//
// Register offsets verified against Nordic's nRF52840 Product
// Specification during this port's feasibility spike:
// docs/superpowers/specs/2026-08-09-nrf52840-support-design.md.
private let pinCnfBase: UInt32 = GPIORegisters.base + 0x700

private func pinCnfAddress(_ pin: Int32) -> UnsafeMutablePointer<UInt32> {
    UnsafeMutablePointer<UInt32>(bitPattern: UInt(pinCnfBase + UInt32(pin) * 4))!
}

private let pinCnfDirInput: UInt32 = 0 << 0
private let pinCnfDirOutput: UInt32 = 1 << 0
private let pinCnfInputConnect: UInt32 = 0 << 1
private let pinCnfInputDisconnect: UInt32 = 1 << 1
private let pinCnfPullDisabled: UInt32 = 0 << 2
private let pinCnfPullDown: UInt32 = 1 << 2
private let pinCnfPullUp: UInt32 = 3 << 2
private let pinCnfDriveS0S1: UInt32 = 0 << 8

// Two wiring conventions — see the matching comment in
// Sources/smk/KeyMatrix.swift. Only P0 (GPIO 0-31) is wired here — see
// GPIORegisters.swift's own note on why P1 is unused for this board.
func init_keyboard_pins(_ rows: UnsafePointer<Int32>, _ rowCount: Int32, _ cols: UnsafePointer<Int32>, _ colCount: Int32, _ colsAreDriven: Int32) {
    if colsAreDriven != 0 {
        // Rows: inputs with pull-downs (sense lines)
        for i in 0..<Int(rowCount) {
            pinCnfAddress(rows[i]).pointee = pinCnfDirInput | pinCnfInputConnect | pinCnfPullDown | pinCnfDriveS0S1
        }
        // Columns: push-pull outputs, idle LOW (strobe lines)
        for i in 0..<Int(colCount) {
            let pin = cols[i]
            pinCnfAddress(pin).pointee = pinCnfDirOutput | pinCnfInputDisconnect | pinCnfPullDisabled | pinCnfDriveS0S1
            gpio.outClear = UInt32(1 << pin)
        }
    } else {
        // Rows: push-pull outputs, idle HIGH (strobe lines)
        for i in 0..<Int(rowCount) {
            let pin = rows[i]
            pinCnfAddress(pin).pointee = pinCnfDirOutput | pinCnfInputDisconnect | pinCnfPullDisabled | pinCnfDriveS0S1
            gpio.outSet = UInt32(1 << pin)
        }
        // Columns: inputs with pull-ups (sense lines) — key press pulls to GND
        for i in 0..<Int(colCount) {
            pinCnfAddress(cols[i]).pointee = pinCnfDirInput | pinCnfInputConnect | pinCnfPullUp | pinCnfDriveS0S1
        }
    }
}
```

- [ ] **Step 1: Write `MpslGlue.swift`**

Per MPSL's documented interrupt contract (`nrfxlib/mpsl/doc/mpsl.rst`, read during this plan's research): MPSL auto-enables `RTC0` and `POWER_CLOCK` interrupts internally via `mpsl_init`, and the application-chosen `low_prio_irq`; the application must itself enable+forward `RADIO` (priority 0 / `MPSL_HIGH_IRQ_PRIORITY`) and `POWER_CLOCK` (any priority, forwarding to `MPSL_IRQ_CLOCK_Handler`). `IRQn_Type` values verified against the vendored `nrf52840.h` (Task 1) during this plan's research: `POWER_CLOCK_IRQn = 0`, `RADIO_IRQn = 1`, `SWI0_EGU0_IRQn = 20`.

Create `ports/nrf52840/MpslGlue.swift`:

```swift
// MPSL (Multiprotocol Service Layer) bring-up — required by the
// SoftDevice Controller (see BleHidSdc.swift/ble_hid_sdc.c, Task 7).
// Vendored API from ${NRFXLIB_PATH}/mpsl/include/mpsl.h. This project has
// no other radio protocol running (no Timeslot API use, no coexistence),
// so MPSL's role here is purely "provide RADIO/RTC0/timer scheduling for
// SDC."
//
// IRQn_Type values below are raw Int32s mirroring the vendored
// nrf52840.h's enum (Embedded Swift doesn't import that C enum here,
// matching this project's established @_extern(c)-only C interop style —
// see e.g. Sources/smk/GPIOInit.swift's GPIO_MODE_INPUT/OUTPUT constants
// for the same pattern) — verified during this port's feasibility spike,
// docs/superpowers/specs/2026-08-09-nrf52840-support-design.md.
private let powerClockIRQn: Int32 = 0
private let radioIRQn: Int32 = 1
// An otherwise-unused peripheral IRQ, per MPSL's "low_prio_irq" contract
// (nrfxlib/mpsl/doc/mpsl.rst): any IRQ not already claimed by a real
// peripheral this board uses. SWI0_EGU0 (Software Interrupt 0 / Event
// Generator Unit 0) is the conventional choice — unused on this board,
// matching nRF Connect SDK's own default for CONFIG_MPSL_LOW_PRIO_IRQN.
private let mpslLowPrioIRQn: Int32 = 20

@_extern(c, "mpsl_init")
func mpsl_init(_ clockConfig: UnsafeRawPointer?, _ lowPrioIRQ: Int32, _ assertHandler: @convention(c) (UnsafePointer<CChar>?, UInt32) -> Void) -> Int32

@_extern(c, "mpsl_low_priority_process")
func mpsl_low_priority_process()

@_extern(c, "MPSL_IRQ_CLOCK_Handler")
func MPSL_IRQ_CLOCK_Handler()

@_extern(c, "NVIC_SetPriority")
func NVIC_SetPriority(_ irqn: Int32, _ priority: UInt32)

@_extern(c, "NVIC_EnableIRQ")
func NVIC_EnableIRQ(_ irqn: Int32)

@_cdecl("smk_mpsl_assert_handler")
func smk_mpsl_assert_handler(_ file: UnsafePointer<CChar>?, _ line: UInt32) {
    while true {}
}

@_cdecl("mpsl_glue_init")
func mpsl_glue_init() {
    // nil clock config = default RC low-frequency clock source (per
    // mpsl_init's doc comment). A real crystal LFCLK config improves BLE
    // timing accuracy/power but isn't needed to link/boot — deferred to
    // hardware bring-up, matching this plan's build-only scope.
    let err = mpsl_init(nil, mpslLowPrioIRQn, smk_mpsl_assert_handler)
    if err != 0 {
        while true {} // fatal — nothing meaningful to do without MPSL
    }

    NVIC_SetPriority(radioIRQn, 0) // MPSL_HIGH_IRQ_PRIORITY, per mpsl.rst
    NVIC_EnableIRQ(radioIRQn)

    NVIC_SetPriority(mpslLowPrioIRQn, 5) // lower priority (higher number) than RADIO, per mpsl.rst
    NVIC_EnableIRQ(mpslLowPrioIRQn)
}

// RADIO/RTC0/TIMER0 interrupt handlers are provided by MPSL itself
// (reserved instances, per mpsl.rst — "must not be reconfigured while
// MPSL is enabled"); no application-side handler needed for those beyond
// the NVIC_EnableIRQ(radioIRQn) above (RTC0's is auto-enabled by
// mpsl_init). POWER_CLOCK is NOT auto-enabled and needs an explicit
// application-provided handler forwarding to MPSL — same @_cdecl
// mechanism app_main_swift uses to be found by name, here found by the
// vector table in gcc_startup_nrf52840.S instead of C's main().
@_cdecl("POWER_CLOCK_IRQHandler")
func POWER_CLOCK_IRQHandler() {
    MPSL_IRQ_CLOCK_Handler()
    // Task 8 note: TinyUSB's dcd_nrf5x.c also needs POWER_CLOCK events
    // (VBUS detect) — this handler will need to also call TinyUSB's power
    // event forwarding once that wiring is finalized in Task 8.
}

// Application must call this promptly (per mpsl.rst, "within a couple of
// ms") whenever mpslLowPrioIRQn fires. Wired from platform_glue.c's
// vTaskDelay shim (called every scan tick, same as kb_usb_task()) rather
// than from the ISR itself — matches this project's existing
// poll-from-the-cooperative-loop style (see ble_kbd_uart_poll() in
// ports/rp2040/platform/ble_hid_kbd_uart.c for the RP2040 equivalent
// pattern).
@_cdecl("mpsl_glue_poll")
func mpsl_glue_poll() {
    mpsl_low_priority_process()
}

@_cdecl("SWI0_EGU0_IRQHandler")
func SWI0_EGU0_IRQHandler() {
    // Intentionally empty — mpsl_glue_poll() is called unconditionally
    // from the main loop every tick rather than gated on this ISR firing,
    // simplest correct thing without hardware in hand to tune polling
    // latency against. Revisit if hardware testing shows this needs to be
    // interrupt-driven instead.
}
```

// "read" half of this transport (send_packet above is the "write" half).

// cooperative-polling style as mpsl_glue_poll()/kb_usb_task().
void sdc_transport_poll(void) {
    static uint8_t msg_buf[HCI_MSG_BUFFER_MAX_SIZE];
    uint8_t msg_type;
    while (sdc_hci_get(msg_buf, &msg_type) == 0) {
        if (!s_packet_handler) continue;

            case SDC_HCI_MSG_TYPE_EVT:
