# STM32F4 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `ports/stm32f4/` as a new SMK build target for the WeAct Black Pill (STM32F411CEU6, Arm Cortex-M4F), covering USB HID, build-only (no hardware on hand).

**Architecture:** New port directory mirroring `ports/nrf52840/`'s shape (hand-rolled `CMakeLists.txt`, no vendor-SDK CMake integration to piggyback on). GPIO and USB HID follow patterns already proven in the existing ports. The genuinely new piece is clock bring-up: this chip boots on a 16MHz internal oscillator and needs explicit RCC/PLL configuration (HSE → PLL → 96MHz SYSCLK, with an exact 48MHz USB clock derived via PLLQ) before USB can work at all — no existing port in this repo has PLL math this involved.

**Tech Stack:** Embedded Swift (`armv7em-none-none-eabi`, soft-float — same triple as the nRF52840 port, re-verified working on this session's toolchain), `arm-gcc-bin@14`, CMake/Ninja, STMicroelectronics' `cmsis-device-f4` (device headers + startup assembly only — no GCC linker script is shipped there, confirmed by this plan's research), ARM's `CMSIS_6` (Cortex-M4 core headers, a separate repo from `cmsis-device-f4` — confirmed by this plan's research that `cmsis-device-f4` does not bundle these), TinyUSB (`dwc2` portable driver, STM32 variant).

## Global Constraints

- **Build-only**: no Black Pill hardware confirmed on hand. No flash/HID verification — every task's regression check is "does it build and link cleanly."
- **Board**: WeAct Black Pill, **STM32F411CEU6 variant specifically** (512KB flash, 128KB RAM, 25MHz HSE crystal — WeAct's documented default, confirmed by this plan's research). If your physical board is actually the F401 variant, the clock math in Task 2 does not apply as-is (F401 tops out at 84MHz, has no PLLI2S) — flag this before running Task 2 if so.
- **Chip/ABI**: Arm Cortex-M4F, **soft-float** throughout (`armv7em-none-none-eabi` on the Swift side, `-mfloat-abi=soft` on the C/ASM side) — verified via this session's `swiftc` against `swift-6.3.1-RELEASE.xctoolchain` that this triple typechecks with a real stdlib; `armv7em-none-none-eabihf` (hard-float) has none. Same conclusion the nRF52840 port already reached on the same core family.
- **Vendor dependencies**, three plain git-clonable directories referenced by env vars (same pattern as `PICO_SDK_PATH`/`NRF5_SDK_PATH`):
  - `CMSIS_F4_PATH` → `git clone https://github.com/STMicroelectronics/cmsis-device-f4`. Only `Include/` (device headers) and `Source/Templates/gcc/startup_stm32f411xe.s` + `Source/Templates/system_stm32f4xx.c` are used. **This repo ships no GCC linker script** (confirmed via its GitHub tree — only ARM/IAR toolchain templates exist under `Source/Templates/`) — Task 1 hand-writes one.
  - `CMSIS_CORE_PATH` → `git clone https://github.com/ARM-software/CMSIS_6`. Only `CMSIS/Core/Include/` (e.g. `core_cm4.h`) is used — `cmsis-device-f4`'s own README states "it is crucial that you use a consistent set of versions for the CMSIS Core - CMSIS Device," confirming these are separate repos, not one bundled tree (same split the nRF5 SDK has between `modules/nrfx/mdk` and `components/toolchain/cmsis`, which `ports/nrf52840/CMakeLists.txt` already handles as two include paths).
  - `TINYUSB_PATH` — already required by RP2040/nRF52840, reused unmodified.
- **Bare-metal cross-compile CMake boilerplate**: `CMAKE_SYSTEM_NAME Generic`, `CMAKE_SYSTEM_PROCESSOR arm`, `CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY` must be set **before** `project()` — without this, CMake's Darwin-host platform module assumes a macOS binary is being built and injects `-arch`/`-isysroot` flags `arm-none-eabi-gcc` rejects. Confirmed necessary during the nRF52840 port (`ports/nrf52840/CMakeLists.txt`'s own comment); the same macOS-host cross-compile detection applies here.
- **Matrix bring-up is single-port only**: `Sources/smk/KeyMatrix.swift`'s shared scan loop calls `gpio.outSet = UInt32(1 << pin)` / `gpio.outClear = ...` / `gpio.input`, treating the pin number as a bit index into **one flat 32-bit register bank** — true for ESP32-C6/RP2040/nRF52840 (each exposes GPIO as one wide register or one 32-pin port), but STM32F4 splits pins across multiple 16-pin-wide ports (GPIOA, GPIOB, ...), each with its own register block. This plan does not modify `KeyMatrix.swift` to add port-encoding, so **this pass's bring-up matrix must wire every row and column pin on a single port** — this plan uses **GPIOB** (pins 0-15), chosen because GPIOA carries USB D-/D+ (PA11/PA12) and the Black Pill's onboard user button (PA0). A multi-port matrix needs `KeyMatrix.swift` changes and is deferred to when a real STM32F4 keyboard PCB is designed (see the design spec's Future Work #2).
- **TinyUSB's `dwc2_clock_init()` is a documented no-op on STM32** (verified directly against the vendored `dwc2_stm32.h`: `TU_ATTR_ALWAYS_INLINE static inline void dwc2_clock_init(uint8_t rhport, tusb_role_t role) { (void) rhport; (void) role; }`) — unlike RP2040/nRF52840, where the vendor driver enables its own peripheral clock, **this port's `UsbHid.swift` must explicitly enable `RCC_AHB2ENR_OTGFSEN` and `RCC_AHB1ENR_GPIOAEN`, and configure PA11/PA12 as AF10**, before calling into TinyUSB (Task 5). Skipping this leaves the OTG_FS peripheral unclocked, so every register access inside `dcd_init()` silently does nothing.
- **TinyUSB symbol names**: `tusb_init`/`tud_task`/`tud_hid_ready`/`tud_hid_keyboard_report` are macros or `static inline` functions with no linkable C symbol for `@_extern(c, ...)` to bind to — the same trap the nRF52840 port already hit and fixed. Use the real exported symbols directly, verified against the vendored TinyUSB source and already proven working in `ports/nrf52840/UsbHid.swift`: `tusb_rhport_init`, `tud_task_ext`, `tud_hid_n_ready`, `tud_hid_n_keyboard_report`.
- **`Sources/SMKCore/` is reused unmodified** — this port only adds hardware-touching Swift/C files, never touches shared pure-logic code.
- **New project code favors Swift over C wherever the C calling convention allows it** — matching this project's established precedent (see `Sources/smk/GPIOInit.swift`, `ports/nrf52840/GPIOInit.swift`/`ClockInit`-equivalent work). Concretely: any C API callable via `@_extern(c, ...)` (plain function calls — TinyUSB's `tud_*`/`tusb_*` functions) gets a thin Swift wrapper instead of a `.c` file; any C-linkage entry point a vendor library calls *into* by symbol name (the CMSIS vector table's weak IRQ handler slots) is a Swift function exposed via `@_cdecl(...)`. This does **not** extend to: the C `main()` stub, the CMSIS startup assembly/`SystemInit()` (unmodified vendor source), or `usb_descriptors.c` (macro-computed TinyUSB descriptor tables — same exception already established for the other two ports' equivalent files, see Task 5).

- [ ] **Step 2: Write the linker script**

Create `ports/stm32f4/linker/STM32F411CEUx_FLASH.ld`. Memory map from the STM32F411CEU6 datasheet: 512KB flash starting at `0x08000000`, 128KB SRAM starting at `0x20000000`. Symbol names (`_estack`, `_sidata`, `_sdata`, `_edata`, `_sbss`, `_ebss`) must match exactly what `startup_stm32f411xe.s`'s `Reset_Handler` references — confirmed by reading that file directly during this plan's research.

```ld
MEMORY
{
  FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 512K
  RAM (xrw)   : ORIGIN = 0x20000000, LENGTH = 128K
}

_estack = ORIGIN(RAM) + LENGTH(RAM);
_Min_Heap_Size = 0x400;
_Min_Stack_Size = 0x400;

ENTRY(Reset_Handler)

SECTIONS
{
  .isr_vector :
  {
    . = ALIGN(4);
    KEEP(*(.isr_vector))
    . = ALIGN(4);
  } >FLASH

  .text :
  {
    . = ALIGN(4);
    *(.text)
    *(.text*)
    *(.rodata)
    *(.rodata*)
    *(.glue_7)
    *(.glue_7t)
    *(.eh_frame)
    KEEP (*(.init))
    KEEP (*(.fini))
    . = ALIGN(4);
    _etext = .;
  } >FLASH

  _sidata = LOADADDR(.data);

  .data :
  {
    . = ALIGN(4);
    _sdata = .;
    *(.data)
    *(.data*)
    . = ALIGN(4);
    _edata = .;
  } >RAM AT> FLASH

  .bss :
  {
    . = ALIGN(4);
    _sbss = .;
    *(.bss)
    *(.bss*)
    *(COMMON)
    . = ALIGN(4);
    _ebss = .;
  } >RAM

  ._user_heap_stack :
  {
    . = ALIGN(8);
    PROVIDE ( end = . );
    PROVIDE ( _end = . );
    . = . + _Min_Heap_Size;
    . = . + _Min_Stack_Size;
    . = ALIGN(8);
  } >RAM

  /DISCARD/ :
  {
    libc.a ( * )
    libm.a ( * )
    libgcc.a ( * )
  }
}
```

```cmake
# Vendor dependency paths (env vars, same pattern as PICO_SDK_PATH/NRF5_SDK_PATH)

# non-Darwin value, CMake's Platform/Darwin module assumes we're building a
# macOS host binary and silently injects -arch/-isysroot into every compile
# command, which arm-none-eabi-gcc rejects. Same fix ports/nrf52840/CMakeLists.txt

set(CMAKE_SYSTEM_NAME Generic)

set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)

project(smk_stm32f4 C ASM)

set(CMAKE_C_STANDARD 11)
set(CMAKE_C_COMPILER arm-none-eabi-gcc)
set(CMAKE_ASM_COMPILER arm-none-eabi-gcc)
set(CMAKE_EXE_LINKER_FLAGS "${CMAKE_EXE_LINKER_FLAGS} -T${LINKER_SCRIPT}")

set(C_ASM_FLAGS
    -mcpu=cortex-m4
    -mthumb
    -mfloat-abi=soft
    -DSTM32F411xE
    -DHSE_VALUE=25000000U
)
add_compile_options(${C_ASM_FLAGS})

# Swift toolchain discovery — same real-stdlib-typecheck probe pattern as
# ports/rp2040/CMakeLists.txt and ports/nrf52840/CMakeLists.txt. armv7em-none-none-eabi
# has a real stdlib on every currently-installed toolchain (re-verified
# during this port's planning, docs/superpowers/specs/2026-08-10-stm32f4-support-design.md),
# so no board-keyed probe-target branching is needed here.

set(SMK_SWIFT_TARGET "armv7em-none-none-eabi")

if(NOT SWIFTC_PATH OR NOT EXISTS "${SWIFTC_PATH}")
    if(DEFINED ENV{SWIFTC_PATH} AND EXISTS "$ENV{SWIFTC_PATH}")
        set(SWIFTC_PATH "$ENV{SWIFTC_PATH}" CACHE PATH "Path to swiftc")
    endif()
endif()

if(NOT SWIFTC_PATH OR NOT EXISTS "${SWIFTC_PATH}")
    set(_tc_dirs
        "$ENV{HOME}/Library/Developer/Toolchains"
        "/Library/Developer/Toolchains"
    )
    set(_smk_probe_src "${CMAKE_BINARY_DIR}/_smk_toolchain_probe.swift")
    file(WRITE "${_smk_probe_src}" "public func _smkToolchainProbe() {}\n")
    foreach(_dir ${_tc_dirs})
        file(GLOB _tcs "${_dir}/*.xctoolchain")
        foreach(_tc ${_tcs})
            set(_sc "${_tc}/usr/bin/swiftc")
            if(EXISTS "${_sc}")
                execute_process(
                    COMMAND "${_sc}" -target ${SMK_SWIFT_TARGET}
                            -enable-experimental-feature Embedded
                            -parse-as-library
                            -typecheck
                            "${_smk_probe_src}"

                )

                    set(SWIFTC_PATH "${_sc}" CACHE PATH "Path to swiftc")
                    break()
                endif()
            endif()
        endforeach()
        if(SWIFTC_PATH)

        endif()

endif()

if(NOT SWIFTC_PATH OR NOT EXISTS "${SWIFTC_PATH}")
    message(FATAL_ERROR
        "Swift compiler (swiftc) supporting ${SMK_SWIFT_TARGET} Embedded (with a "
        "real stdlib for it) not found.\n"
        "Set SWIFTC_PATH to the path of a compatible swiftc, e.g.:\n"

        "<toolchain>.xctoolchain/usr/bin/swiftc ...")
endif()
message(STATUS "Using Swift compiler: ${SWIFTC_PATH}")

# newlib headers live. Same fix ports/nrf52840/CMakeLists.txt already needed
# (see that file's own comment for the full story) — ask the real compiler
# directly via `-E -Wp,-v` on an empty source, which dumps its exact system
# include search path to stderr.
execute_process(
    COMMAND ${CMAKE_C_COMPILER} ${C_ASM_FLAGS} -E -Wp,-v -xc /dev/null
    ERROR_VARIABLE _stm32f4_gcc_include_dump
    OUTPUT_QUIET
)
string(REGEX MATCH "search starts here:\n(.*)\nEnd of search list" _stm32f4_gcc_include_match "${_stm32f4_gcc_include_dump}")
string(REGEX REPLACE "\n" ";" _stm32f4_gcc_include_lines "${CMAKE_MATCH_1}")
set(STM32F4_GCC_XCC_INCLUDES "")
foreach(_line ${_stm32f4_gcc_include_lines})
    string(STRIP "${_line}" _dir)
    if(_dir)
        list(APPEND STM32F4_GCC_XCC_INCLUDES "-Xcc" "-I${_dir}")
    endif()
endforeach()
if(NOT STM32F4_GCC_XCC_INCLUDES)
    message(FATAL_ERROR "Failed to determine arm-none-eabi-gcc's system include search path. Command output:\n${_stm32f4_gcc_include_dump}")
endif()
```

```c
// Task 1 stub — minimal C entry point calling into the Swift smoke test.
// Replaced with the real platform_glue.c (kb_log, vTaskDelay, etc.) in
// Task 4, matching ports/nrf52840/platform/platform_glue.c's role.
//
// posix_memalign/_init are needed even for this minimal smoke test:
// Swift's Embedded runtime (swift_allocObject/swift_slowAlloc)
// unconditionally references posix_memalign, and
// startup_stm32f411xe.s's Reset_Handler unconditionally calls
// __libc_init_array (which calls _init) before main(). _init would
// normally come from crti.o/crtn.o, but this project's -nostartfiles
// excludes those, so a trivial no-op stub is needed. The rest of
// newlib's syscall stubs (_exit/_sbrk/_write/_read/etc.) are satisfied
// by Step 3's --specs=nosys.specs link flag instead of hand-written
// stubs here.
#include <errno.h>
#include <malloc.h>
#include <stddef.h>

extern void app_main_swift(void);

int posix_memalign(void **memptr, size_t alignment, size_t size) {
    if (alignment == 0 || (alignment & (alignment - 1)) != 0) return EINVAL;
    if (size == 0) { *memptr = NULL; return 0; }
    void *p = memalign(alignment, size);
    if (p == NULL) return ENOMEM;
    *memptr = p;
    return 0;
}

void _init(void) {}

int main(void) {
    app_main_swift();
    return 0;
}
```

- [ ] **Step 1: Write `ClockInit.swift`**

PLL math: with HSE=25MHz, PLLM=25 gives a 1MHz VCO input (spec range: 1-2MHz); PLLN=384 gives a 384MHz VCO output (spec range: 100-432MHz); PLLP=4 gives SYSCLK=384/4=96MHz; PLLQ=8 gives the USB clock=384/8=48MHz exactly (USB full-speed requires exactly 48MHz, not "close to"). 96MHz needs Power Scale 1 (the POR default is Scale 2, which caps out at 84MHz) and 3 flash wait states (RM0383's wait-state table: 90-100MHz at 2.7-3.6V needs `LATENCY=3`). APB1's 50MHz max requires dividing SYSCLK by 2 (→48MHz); APB2's 100MHz max needs no division.

Create `ports/stm32f4/ClockInit.swift`:

```swift
// STM32F411CEU6 RCC/PLL clock bring-up: HSE (25MHz, WeAct Black Pill's
// crystal) -> main PLL -> 96MHz SYSCLK, with PLLQ deriving an exact 48MHz
// USB OTG FS clock. See this plan's Task 2 for the PLL math and the
// register offsets' verification (RM0383 + cmsis-device-f4's headers).
//
// This is a busy-wait bring-up routine with no timeout: if HSE or the PLL
// never locks, there is nothing meaningful to do but hang — same fail-stop
// pattern ports/nrf52840/MpslGlue.swift uses for mpsl_init failures.

private let rccBase: UInt32 = 0x40023800
private let rccCr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(rccBase + 0x00))!
private let rccPllcfgr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(rccBase + 0x04))!
private let rccCfgr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(rccBase + 0x08))!
private let rccApb1Enr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(rccBase + 0x40))!

private let pwrBase: UInt32 = 0x40007000
private let pwrCr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(pwrBase + 0x00))!

private let flashBase: UInt32 = 0x40023C00
private let flashAcr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(flashBase + 0x00))!

private let rccCrHseOn: UInt32 = 1 << 16
private let rccCrHseRdy: UInt32 = 1 << 17
private let rccCrPllOn: UInt32 = 1 << 24
private let rccCrPllRdy: UInt32 = 1 << 25

private let rccApb1EnrPwrEn: UInt32 = 1 << 28
private let pwrCrVosMask: UInt32 = 0b11 << 14
private let pwrCrVosScale1: UInt32 = 0b11 << 14 // reset default is Scale 2 (0b10) — Scale 1 needed above 84MHz

private let flashAcrLatency3Ws: UInt32 = 0b011      // RM0383 Table 10: 90-100MHz @ 2.7-3.6V
private let flashAcrPrften: UInt32 = 1 << 8
private let flashAcrIcen: UInt32 = 1 << 9
private let flashAcrDcen: UInt32 = 1 << 10

private let pllM: UInt32 = 25   // HSE(25MHz)/25 = 1MHz VCO input
private let pllN: UInt32 = 384  // 1MHz*384 = 384MHz VCO output
private let pllPBits: UInt32 = 0b01 // encoding: 00=/2 01=/4 10=/6 11=/8 -> PLLP=4, SYSCLK=384/4=96MHz
private let pllQ: UInt32 = 8    // 384/8 = 48MHz USB clock (must be exact)
private let rccPllcfgrPllsrcHse: UInt32 = 1 << 22

private let rccCfgrSwMask: UInt32 = 0b11
private let rccCfgrSwPll: UInt32 = 0b10
private let rccCfgrSwsMask: UInt32 = 0b11 << 2
private let rccCfgrSwsPll: UInt32 = 0b10 << 2
private let rccCfgrPpre1Mask: UInt32 = 0b111 << 10
private let rccCfgrPpre1Div2: UInt32 = 0b100 << 10 // APB1 max 50MHz: 96/2 = 48MHz

@_cdecl("smk_clock_init")
func smk_clock_init() {
    // 1. Start HSE and wait for it to stabilize.
    rccCr.pointee |= rccCrHseOn
    while (rccCr.pointee & rccCrHseRdy) == 0 {}

    // 2. Power interface clock + Voltage Scale 1 (required above 84MHz).
    rccApb1Enr.pointee |= rccApb1EnrPwrEn
    pwrCr.pointee = (pwrCr.pointee & ~pwrCrVosMask) | pwrCrVosScale1

    // 3. Flash wait states for 96MHz, plus prefetch/instruction/data caches.
    flashAcr.pointee = flashAcrLatency3Ws | flashAcrPrften | flashAcrIcen | flashAcrDcen

    // 4. Configure the main PLL from HSE: PLLM/PLLN/PLLP/PLLQ, source = HSE.
    //    Must be written while the PLL is off (true here — POR default).
    rccPllcfgr.pointee = pllM | (pllN << 6) | (pllPBits << 16) | rccPllcfgrPllsrcHse | (pllQ << 24)

    // 5. Enable the PLL and wait for lock.
    rccCr.pointee |= rccCrPllOn
    while (rccCr.pointee & rccCrPllRdy) == 0 {}

    // 6. APB1 /2 (48MHz, within its 50MHz max); APB2 and AHB stay undivided
    //    (96MHz, within APB2's 100MHz max and AHB's 100MHz max) — both
    //    already 0 (not divided) at reset, so only PPRE1 needs setting.
    rccCfgr.pointee = (rccCfgr.pointee & ~rccCfgrPpre1Mask) | rccCfgrPpre1Div2

    // 7. Switch SYSCLK to the PLL and wait for the switch to take effect.
    rccCfgr.pointee = (rccCfgr.pointee & ~rccCfgrSwMask) | rccCfgrSwPll
    while (rccCfgr.pointee & rccCfgrSwsMask) != rccCfgrSwsPll {}
}
```

- [ ] **Step 1: Write `GPIORegisters.swift`**

```swift
// STM32F4 GPIO register access — GPIOB only. See this plan's Global
// Constraints: Sources/smk/KeyMatrix.swift treats gpio.outSet/outClear/input
// as one flat 32-bit bank (bit == GPIO number), which doesn't natively span
// STM32's multiple 16-pin-wide GPIO ports without changing shared code
// (not done in this pass). GPIOB is used for the whole matrix (rows AND
// columns) since GPIOA carries USB D-/D+ (PA11/PA12, see UsbHid.swift) and
// the Black Pill's onboard user button (PA0).
//
// Register offsets verified against cmsis-device-f4's GPIO_TypeDef
// (Include/stm32f411xe.h) during this plan's research.
//
// GPIOB base address: 0x4002_0400 (AHB1PERIPH_BASE + 0x0400)
//   0x14  ODR   (read: current output state)
//   0x18  BSRR  (write-only: bits[15:0] atomic set, bits[31:16] atomic reset)
//   0x10  IDR   (read: current input level, bit == pin number 0-15)
struct GPIORegisters {
    static let base: UInt32 = 0x40020400 // GPIOB

    let baseAddress: UnsafeMutablePointer<UInt32>

    init(address: UInt32) {
        self.baseAddress = UnsafeMutablePointer<UInt32>(bitPattern: UInt(address))!
    }

    // 0x18 (low half): BSRR — writing a 1 atomically sets the corresponding output high.
    var outSet: UInt32 {
        get { baseAddress.advanced(by: 5).pointee } // 0x14: ODR, current state
        nonmutating set { baseAddress.advanced(by: 6).pointee = newValue & 0x0000_FFFF }
    }

    // 0x18 (high half): BSRR — writing a 1 (shifted to bits[31:16]) atomically drives the corresponding output low.
    var outClear: UInt32 {
        get { baseAddress.advanced(by: 5).pointee } // 0x14: ODR, current state
        nonmutating set { baseAddress.advanced(by: 6).pointee = (newValue & 0x0000_FFFF) << 16 }
    }

    // 0x10: IDR — current input level of every GPIOB pin (bit == pin number, 0-15).
    var input: UInt32 {
        get { baseAddress.advanced(by: 4).pointee }
    }
}

// Instantiate the bank at the STM32F411's GPIOB base address.
let gpio = GPIORegisters(address: GPIORegisters.base)
```

- [ ] **Step 2: Write `GPIOInit.swift`**

`MODER`/`PUPDR` are 2-bit fields per pin (pin N at bits `[2N+1:2N]`) — verified against `cmsis-device-f4`'s header during this plan's research. `OTYPER` (push-pull vs. open-drain) and `OSPEEDR` (slew rate) both default to push-pull/low-speed at reset, which is correct for this matrix (push-pull strobes, no need for open-drain; low speed is plenty for a debounced key scan), so neither is touched here.

Create `ports/stm32f4/GPIOInit.swift`:

```swift
// STM32F4 matrix pin configuration (GPIOB only — see GPIORegisters.swift's
// header comment on the single-port constraint). Plain Swift: MODER/PUPDR
// are raw registers, no vendor driver call to wrap, same style
// ports/nrf52840/GPIOInit.swift already establishes for that port's PIN_CNF.
//
// Register bit layout verified against cmsis-device-f4's GPIO_TypeDef
// (Include/stm32f411xe.h) during this plan's research.
private let moderBase = UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x00))!
private let pupdrBase = UnsafeMutablePointer<UInt32>(bitPattern: UInt(GPIORegisters.base + 0x0C))!

private let moderInput: UInt32 = 0b00
private let moderOutput: UInt32 = 0b01
private let pupdrNone: UInt32 = 0b00
private let pupdrUp: UInt32 = 0b01
private let pupdrDown: UInt32 = 0b10

private func setTwoBitField(_ register: UnsafeMutablePointer<UInt32>, pin: Int32, value: UInt32) {
    let shift = UInt32(pin) * 2
    let mask: UInt32 = 0b11 << shift
    register.pointee = (register.pointee & ~mask) | (value << shift)
}

// RCC_AHB1ENR (RCC base 0x4002_3800 + 0x30) bit 1 = GPIOBEN. Must be
// enabled before touching any GPIOB register — verified against
// cmsis-device-f4's RCC_TypeDef during this plan's research.
private let rccAhb1Enr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(0x40023800 + 0x30))!
private let rccAhb1EnrGpiobEn: UInt32 = 1 << 1

// Two wiring conventions — see the matching comment in Sources/smk/KeyMatrix.swift.
// All pins here are GPIOB (0-15) — see this plan's Global Constraints.
func init_keyboard_pins(_ rows: UnsafePointer<Int32>, _ rowCount: Int32, _ cols: UnsafePointer<Int32>, _ colCount: Int32, _ colsAreDriven: Int32) {
    rccAhb1Enr.pointee |= rccAhb1EnrGpiobEn

    if colsAreDriven != 0 {
        // Rows: inputs with pull-downs (sense lines)
        for i in 0..<Int(rowCount) {
            setTwoBitField(moderBase, pin: rows[i], value: moderInput)
            setTwoBitField(pupdrBase, pin: rows[i], value: pupdrDown)
        }
        // Columns: push-pull outputs, idle LOW (strobe lines)
        for i in 0..<Int(colCount) {
            let pin = cols[i]
            setTwoBitField(moderBase, pin: pin, value: moderOutput)
            setTwoBitField(pupdrBase, pin: pin, value: pupdrNone)
            gpio.outClear = UInt32(1 << pin)
        }
    } else {
        // Rows: push-pull outputs, idle HIGH (strobe lines)
        for i in 0..<Int(rowCount) {
            let pin = rows[i]
            setTwoBitField(moderBase, pin: pin, value: moderOutput)
            setTwoBitField(pupdrBase, pin: pin, value: pupdrNone)
            gpio.outSet = UInt32(1 << pin)
        }
        // Columns: inputs with pull-ups (sense lines) — key press pulls to GND
        for i in 0..<Int(colCount) {
            setTwoBitField(moderBase, pin: cols[i], value: moderInput)
            setTwoBitField(pupdrBase, pin: cols[i], value: pupdrUp)
        }
    }
}
```

- [ ] **Step 2: Write `UsbHid.swift`**

Per this plan's Global Constraints, two things this file must do that the other ports' equivalents don't: (1) explicitly enable the OTG_FS peripheral's and GPIOA's RCC clocks and configure PA11/PA12 as AF10 before calling into TinyUSB (`dwc2_clock_init()` is a documented no-op on STM32 — verified against the vendored `dwc2_stm32.h`); (2) use the same real TinyUSB symbol names `ports/nrf52840/UsbHid.swift` already established (`tusb_rhport_init`/`tud_task_ext`/`tud_hid_n_ready`/`tud_hid_n_keyboard_report`), not the macro/`static inline` names a naive first draft might reach for.

PA11/PA12 AF10 register layout: `GPIOA` base `0x40020000`; `MODER` bits `[23:22]`/`[25:24]` = `10` (alternate function mode) for pins 11/12; `AFRH` (`+0x24`) is a 4-bit-per-pin alternate-function selector for pins 8-15, so PA11 is bits `[15:12]` and PA12 is bits `[19:16]`; AF10 = `0b1010`. `RCC_AHB1ENR` (`0x40023800+0x30`) bit 0 = `GPIOAEN`; `RCC_AHB2ENR` (`0x40023800+0x34`) bit 7 = `OTGFSEN`. All verified against `cmsis-device-f4`'s headers during this plan's research.

Create `ports/stm32f4/UsbHid.swift`:

```swift
// STM32F4 USB HID glue via TinyUSB's dwc2 driver (OTG_FS peripheral). The
// "wired" half of the SMK contract — this board has no BLE this pass.
//
// Real TinyUSB symbol names (not the macro/static-inline names): see this
// plan's Global Constraints — tusb_init/tud_task/tud_hid_ready/
// tud_hid_keyboard_report have no linkable C symbol; ports/nrf52840/UsbHid.swift
// already established (and verified against the vendored source) the real
// exported equivalents used below.

private let gpioaBase: UInt32 = 0x40020000
private let gpioaModer = UnsafeMutablePointer<UInt32>(bitPattern: UInt(gpioaBase + 0x00))!
private let gpioaAfrh = UnsafeMutablePointer<UInt32>(bitPattern: UInt(gpioaBase + 0x24))!

private let rccAhb1Enr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(0x40023800 + 0x30))!
private let rccAhb2Enr = UnsafeMutablePointer<UInt32>(bitPattern: UInt(0x40023800 + 0x34))!
private let rccAhb1EnrGpioaEn: UInt32 = 1 << 0
private let rccAhb2EnrOtgfsEn: UInt32 = 1 << 7

private let afAlternateFunctionMode: UInt32 = 0b10
private let af10: UInt32 = 0b1010

// dwc2_clock_init() (TinyUSB's ports/synopsys/dwc2/dwc2_stm32.h) is a
// documented no-op on STM32 — this project's own equivalent of enabling the
// OTG_FS peripheral clock and muxing PA11/PA12 to AF10 (verified against
// that vendored header during this plan's research). Must run before
// init_wired_link() below.
private func enableUsbClockAndPins() {
    rccAhb1Enr.pointee |= rccAhb1EnrGpioaEn
    rccAhb2Enr.pointee |= rccAhb2EnrOtgfsEn

    // PA11 = D-, PA12 = D+, both alternate-function mode, AF10 (OTG_FS).
    let moderMask: UInt32 = (0b11 << 22) | (0b11 << 24)
    let moderValue: UInt32 = (afAlternateFunctionMode << 22) | (afAlternateFunctionMode << 24)
    gpioaModer.pointee = (gpioaModer.pointee & ~moderMask) | moderValue

    let afrhMask: UInt32 = (0b1111 << 12) | (0b1111 << 16)
    let afrhValue: UInt32 = (af10 << 12) | (af10 << 16)
    gpioaAfrh.pointee = (gpioaAfrh.pointee & ~afrhMask) | afrhValue
}

@_extern(c, "tusb_rhport_init")
func tusb_rhport_init(_ rhport: UInt8, _ rhInit: UnsafeRawPointer?) -> Bool

@_extern(c, "tud_task_ext")
func tud_task_ext(_ timeoutMs: UInt32, _ inIsr: Bool)

@_extern(c, "tud_hid_n_ready")
func tud_hid_n_ready(_ instance: UInt8) -> Bool

@_extern(c, "tud_hid_n_keyboard_report")
func tud_hid_n_keyboard_report(_ instance: UInt8, _ reportID: UInt8, _ modifier: UInt8, _ keycode: UnsafePointer<UInt8>) -> Bool

// Implemented in platform/usb_descriptors.c — crosses the Swift/C boundary,
// needs @_extern(c, ...), matching this file's own tud_*/tusb_* declarations.
@_extern(c, "smk_keymap_usb_service")
func smk_keymap_usb_service()

// OTG_FS interrupt forwarding: without this, OTG_FS_IRQHandler in the
// vector table (startup_stm32f411xe.s, CMSIS's default weak alias) falls
// through to Default_Handler (an infinite loop), and dwc2's dcd_init()
// (called via tusb_rhport_init below) unconditionally enables
// NVIC_EnableIRQ(OTG_FS_IRQn) (verified against the vendored dwc2_stm32.h's
// dwc2_dcd_int_enable). So the very first USB event after init_wired_link()
// runs would hang the firmware — same class of bug ports/nrf52840/UsbHid.swift's
// USBD_IRQHandler and MpslGlue.swift's interrupt forwarders fix for that
// port. `tusb_int_handler` is TinyUSB's real exported ISR body
// (src/tusb.c), verified directly against the vendored source.
@_extern(c, "tusb_int_handler")
func tusb_int_handler(_ rhport: UInt8, _ inIsr: Bool)

@_cdecl("OTG_FS_IRQHandler")
func OTG_FS_IRQHandler() {
    tusb_int_handler(0, true)
}

func init_wired_link() {
    enableUsbClockAndPins()
    _ = tusb_rhport_init(0, nil)
}

// Pump TinyUSB. Called every scan tick from platform_glue.c's vTaskDelay
// via its own `extern void kb_usb_task(void);` declaration — a real
// Swift/C boundary crossing, so @_cdecl (unlike init_wired_link/
// send_wired_report below, called only from Main.swift, plain Swift-to-
// Swift same-module resolution).
@_cdecl("kb_usb_task")
func kb_usb_task() {
    tud_task_ext(UInt32.max, false) // wait-forever, not-in-ISR
    smk_keymap_usb_service()
}

// Send a standard 8-byte boot-keyboard report: [modifier][reserved][6 keys].
func send_wired_report(_ modifier: UInt8, _ keys: UnsafePointer<UInt8>) {
    guard tud_hid_n_ready(0) else { return }
    _ = tud_hid_n_keyboard_report(0, 0, modifier, keys)
}

// TinyUSB requires this when CFG_TUSB_OS == OPT_OS_NONE (no RTOS) — same
// requirement ports/nrf52840/UsbHid.swift's tusb_time_millis_api already
// documents (verified against the vendored tusb.c). Uncalibrated per-call
// counter, NOT a real millisecond clock — no hardware timer wired up yet.
private var s_millisCounter: UInt32 = 0

@_cdecl("tusb_time_millis_api")
func tusb_time_millis_api() -> UInt32 {
    s_millisCounter &+= 1
    return s_millisCounter
}
```
