# RP2350 (Pico 2 / Pico 2 W) Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `pico2` and `pico2_w` as buildable `SMK_TARGET_BOARD` values in the RP2040 port, producing a clean `.uf2`/`.elf` for both via `./build_rp2040.sh pico2` / `pico2_w`.

**Architecture:** RP2350 runs Arm Cortex-M33 (Armv8-M Mainline) in this port. `ports/rp2040/CMakeLists.txt` grows a board-keyed branch that swaps the Swift `-target` triple and `-Xcc` arch/float flags (`armv8m.main-none-none-eabi` / `softfp` instead of `armv6m-none-none-eabi` / `soft`), and sets `PICO_NO_CMSE=1` early enough to reach pico-sdk's toolchain preload phase. The existing Pico W BTstack/CYW43 BLE branch extends to also match `pico2_w`, since both boards wire CYW43 the same way. `GPIORegisters.swift` needs no functional change — the SIO register layout is identical between RP2040 and RP2350.

**Tech Stack:** CMake 3.29+ (pico-sdk native Swift support), `arm-gcc-bin@14` (already has the `v8-m.main` multilib), Swift 6.3.2 Embedded (`armv8m.main-none-none-eabi` confirmed supported), pico-sdk (already ships `pico2`/`pico2_w` board headers and `rp2350-arm-s` platform preset).

## Global Constraints

- Build-only scope: no RP2350 hardware available, so verification is "produces a `.uf2`/`.elf` cleanly," not flash/HID testing. (Spec: Testing section.)
- `PICO_NO_CMSE=1` for RP2350 boards — no TrustZone secure/non-secure partitioning in this project. (Spec: Design > Core/architecture choice.)
- Swift `-Xcc` flags on RP2350 must mirror pico-sdk's own C-side arch/float flags (`-march=armv8-m.main+fp+dsp -mfloat-abi=softfp -mfpu=fpv5-sp-d16`) rather than forcing soft-float, to avoid ABI mismatches with pico-sdk's prebuilt objects. (Spec: Design > Core/architecture choice.)
- A future RP2350 chip-down board is explicitly out of scope. (Spec: Problem.)

- [ ] **Step 1: Add early RP2350 detection before `pico_sdk_import.cmake`**

`PICO_NO_CMSE` is read by pico-sdk's `cmake/preload/toolchains/pico_arm_cortex_m33_gcc.cmake`, which runs during CMake's toolchain *preload* phase — triggered by `include(pico_sdk_import.cmake)`, i.e. before `project()`/`pico_sdk_init()` and before the file's existing `SMK_TARGET_BOARD` CACHE variable (defined later, at line ~90) is set. Since `build_rp2040.sh` already passes `-DSMK_TARGET_BOARD=...` on the CMake command line, that variable is readable immediately — just not yet defaulted from `PICO_BOARD` if the caller only passed `-DPICO_BOARD=...`. Add this block as the new first thing in the file, replacing the current top:

```cmake
cmake_minimum_required(VERSION 3.29)

# ---------------------------------------------------------------------------
# Early RP2350 detection — must happen before pico_sdk_import.cmake, since
# PICO_NO_CMSE is consumed by pico-sdk's toolchain *preload* phase (which
# runs before project()/pico_sdk_init(), i.e. before the canonical
# SMK_TARGET_BOARD CACHE variable further down this file is set). Mirrors
# that later block's PICO_BOARD fallback so a bare
# `cmake -DPICO_BOARD=pico2 ...` (no explicit -DSMK_TARGET_BOARD) still
# works.
# ---------------------------------------------------------------------------
if(NOT DEFINED SMK_TARGET_BOARD)
    set(SMK_TARGET_BOARD "${PICO_BOARD}")
endif()
if(SMK_TARGET_BOARD STREQUAL "pico2" OR SMK_TARGET_BOARD STREQUAL "pico2_w")
    # No TrustZone secure/non-secure partitioning in this project — disable
    # CMSE codegen (-mcmse) rather than carry its untested interaction with
    # Swift-emitted code for no benefit.
    set(PICO_NO_CMSE 1)
endif()

# ---------------------------------------------------------------------------
# pico-sdk bootstrap — must happen before project()
# ---------------------------------------------------------------------------
if(NOT DEFINED ENV{PICO_SDK_PATH} AND NOT PICO_SDK_PATH)
    set(ENV{PICO_SDK_PATH} "$ENV{HOME}/pico-sdk")
endif()

include(${CMAKE_CURRENT_LIST_DIR}/pico_sdk_import.cmake)
```

Find the existing block that sets `_smk_swift_defs` (currently just above the final `target_compile_options` call, around line 345-348):

Immediately after it, add the arch-flag selection:

```cmake
# RP2350 (Cortex-M33, Armv8-M Mainline) needs a different Swift target
# triple than RP2040 (Cortex-M0+, Armv6-M), plus matching -Xcc arch/float
# flags. RP2350's Cortex-M33 has a real FPU and pico-sdk's own toolchain
# preset (pico_arm_cortex_m33_gcc.cmake) builds its C sources / prebuilt
# objects expecting `-march=armv8-m.main+fp+dsp -mfloat-abi=softfp` — so
# Swift's Clang-importer flags mirror that instead of forcing soft-float
# the way the RP2040/Armv6-M path does (Armv6-M has no FPU at all, so soft
# float there is the only option).
if(SMK_IS_RP2350)
    set(_smk_swift_arch_flags
        "-target armv8m.main-none-none-eabi
        -Xcc -march=armv8-m.main+fp+dsp
        -Xcc -mfloat-abi=softfp
        -Xcc -mfpu=fpv5-sp-d16"
    )
else()
    set(_smk_swift_arch_flags
        "-target armv6m-none-none-eabi
        -Xcc -mfloat-abi=soft"
    )
endif()
```

Then find the final `target_compile_options` call (currently the last block in the file):
